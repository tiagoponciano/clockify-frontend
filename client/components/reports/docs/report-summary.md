# Report summary

This document describes the current Reports summary screen at `/reports` for developers maintaining the frontend and its report API integration.

## What this is

The screen summarizes tracked time for a selected period. It requests the same filtered dataset grouped by day and by project, then presents a daily bar chart, a project table, and a matching donut chart. Users with the `ADMIN` or `LEADER` role can report across the team; a `MEMBER` is always scoped to their own user ID.

The project grouping is the source of truth for the displayed total. The daily chart and project breakdown always receive the same period, client, project, and effective user filters.

## Surface

- Route: `GET /reports`
- Authentication: the authenticated application shell and `AuthGuard`
- Report data: `GET /api/reports/summary`
- Lookup data: `GET /api/clients`, `GET /api/projects`, and, for team-capable roles, `GET /api/users`

The summary endpoint accepts these optional query parameters:

- `from`: inclusive UTC ISO timestamp
- `to`: inclusive UTC ISO timestamp
- `groupBy`: `day` or `project` on this screen
- `clientId`: client identifier
- `projectId`: project identifier
- `userId`: user identifier

## Data shapes

A summary response is an array:

```json
[
  {
    "id": "project-123",
    "name": "Internal tools - NEO",
    "totalSeconds": 19800,
    "color": "#f97316"
  }
]
```

`id` is a project ID when grouped by project, `__unassigned__` for entries without a project, and a local `yyyy-MM-dd` key when grouped by day. `totalSeconds` is a non-negative duration in seconds. `color` is optional; the UI uses the related client color or a deterministic fallback color when it is absent.

The CSV download contains one row per currently filtered project with `Projeto`, formatted `Duração`, raw `Duração em segundos`, and `Participação`. The file uses UTF-8 with a byte-order mark for spreadsheet compatibility. Text that could be interpreted as a spreadsheet formula is prefixed with an apostrophe.

## Rules and behavior

The default period is the current Monday-through-Sunday week in `America/Sao_Paulo`.

Changing the client clears the selected project because the previous project may not belong to the new client. The project selector lists non-archived projects for the selected client, or all non-archived projects when no client is selected. Clearing filters resets client, project, and team member while preserving the selected period.

For `ADMIN` and `LEADER`, no selected team member means the entire team. For `MEMBER`, the current user's ID is always sent and the team selector is hidden.

The total is the sum of all project-grouped `totalSeconds` values. Project participation is computed as:

```text
project totalSeconds / report totalSeconds * 100
```

Participation is displayed with two decimal places. Durations are displayed as unbounded `HH:mm:ss`; hours may exceed 24.

All lookups and both report queries contribute to the loading state. Any failed request shows a retry action that refetches only failed queries. Timer and time-entry mutations invalidate report queries so the next report read uses current data. A successful response with a zero project total shows the empty state instead of charts.

## What this does NOT do

- It does not display billable time, currency, invoice actions, or amounts.
- It does not filter by task, tag, status, or description.
- It does not provide Detailed, Weekly, or Shared report tabs.
- It does not sort or paginate the project table in the browser.
- It does not request entry-level time records.
- CSV export is generated locally and is not stored or generated by the API.

## Gotchas

- A `MEMBER` cannot remove their own user scope. Hiding the team selector does not mean the API request is unscoped.
- Project summary names returned by the mock API include the client name. The table uses project lookup data when available to keep project and client in separate columns.
- Selecting a new client intentionally clears the project, including when returning to all clients.
- The date picker sends UTC bounds derived from São Paulo calendar dates. Building bounds from the browser's local timezone can shift report entries into an adjacent day.
- The mock report endpoint persists time entries in browser local storage, so different browser profiles can show different totals.

## Setup

Set `NEXT_PUBLIC_USE_MOCK_API=true` to use the in-browser mock handlers. Otherwise, configure `NEXT_PUBLIC_API_URL` for a backend that implements the endpoints listed above.
